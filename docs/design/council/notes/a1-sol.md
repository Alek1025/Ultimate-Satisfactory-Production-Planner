Sol Arch R1 ("Factory Atlas"):
Frameworks: Electron (runner-up Tauri; one bundled Chromium, consistent Win/Linux target; sandboxed renderer, narrow IPC). React + TS (runner-up Svelte; dense accessible inspectors/tables). Native HiGHS in cancellable subprocess (runner-up WASM worker; native LP/MIP for discrete decisions; kill solve, recover from crash). Map = tiled Canvas 2D with HTML controls/inspectors (runner-up PixiJS; predictable overlays/hit testing, small renderer, accessible selection via inspector/lists). Storage = versioned SQLite project file (runner-up versioned ZIP + JSON manifest; transactions, backup API for portable copy). Tests: Vitest domain + fixture tests, packaged Windows smoke harness (import, native solver launch, cancellation, interrupted-write recovery); missing golden fixtures fail.
Architecture: local install/user exports -> versioned game catalog; save/preset/manual/future live -> World State snapshots (immutable, stable IDs, timestamps, field provenance, import diagnostics, unknown classes preserved); player goals+pins+budgets -> plan revision + snapshot + catalog -> compile -> HiGHS -> feasibility check (whole buildings, physical caps, real clocks; headlift along route, pump placement, generators tied to fuel/water); plan rev + snapshot(s) -> variance engine -> evidence (observed settings/states, derived capacities, inferred flows, unavailable measurements). Validate local world-catalog extraction as first packaging milestone; support user-supplied catalog exports. Path 2: opt-in loopback-only FRM adapter publishes partial observations via same interface with sample time and coverage; save-pull adapter feeds bytes to parser; marker export = separate outbound adapter. §8: fingerprint at dispatch incl. normalized world/catalog, rule constants, solver build/options; preserve result fingerprints across import; late result stays with its revision; ship install-to-report slice first; incremental commits.
UI: map is the working surface, inspector is where commitments are made; shell shows project, phase, revision, world source; selection carries across. Screens: Atlas (sites, node allocations, corridor budgets, hard limits, circuit headroom), Phases (player milestones, targets, dependencies, constraints), Options (compare forks at same map extent; which assumptions each sensitivity test holds fixed), Variance (plan-to-save deltas, snapshot changes, evidence per number). Flow: locate game data -> save/preset/manual world -> define phase -> inspect/edit checked proposal -> publish revision -> later autosave -> variance report; inspect snapshot before it becomes baseline. Surprise: drag a refinery across a corridor in an Options fork -> tradeoff receipt (freight released, load moved between circuits, how much target survives a tighter budget; e.g. Caterium smelting at quarry removes 240/min from belt, shifts 32 MW).
