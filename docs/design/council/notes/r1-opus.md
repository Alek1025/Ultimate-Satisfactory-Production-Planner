Path A "Copilot" (companion that follows your save): watches SaveGames folder, auto-finds Docs, reloads on autosave, shows diffs (unlocks, phase, Somersloops, built-on nodes), rebases plans, flags stale results. Next phase/milestone costs, power check, nearest free nodes. Later: reads the built factory (machines, clocks, belts) to plan against it ("add 10 Motors/min using what I have"). Everything = everything about YOUR world: progress tracking, inventory/depot holdings, node map taken/free, phase & milestone shopping lists, audit of existing factory, plan history across saves. Leaves out layout/logistics design; save-less planning only a fallback. Good bet: save parser + node catalog are the differentiator; desktop unlocks folder-watching and install detection; no mainstream planner does this offline. Risk: game patches break save format; reading built factories is new unvalidated parsing. Reuses REWRITE-NOTES §1-2, §5, §7, robustness rule.

Path B "Megabase" (world-scale design tool): place factory sites on the map, assign targets and nodes; solver decides what each site makes and what moves between them (trains, drones, trucks, power lines). Per-site breakdown (machine counts, belt tiers, manifolds, floors), build checklist with total material cost; iterate on one big plan over weeks. Everything = multi-site optimization, logistics capacity and cost, power grid (generators, fuel chains, geothermal, batteries), build order and material cost per phase, scenario comparison. Save is optional starting point. Leaves out live tracking and reading built factory. Good bet: uses lexicographic LP + diagnosis where hand calculators fail. Risk: scope and model complexity; slow/opaque solves; "optimal only for the restricted model" compounds. Reuses §4, §6, §7.

Path C "Field Manual" (offline toolkit and reference): codex of every item/recipe/building/schematic plus quick ratio calculator, alternate-recipe rankings (which hard-drive alt to take), MAM/milestone browser, power & clock calculators, belt/pipe tools, node finder, full optimizer as one tool among many. Save personalizes but never required. Everything = breadth. Leaves out multi-factory design and deep save tracking. Good bet: widest audience, value in first minute, works even when a patch breaks the parser. Risk: competes with mature free websites; "a worse wiki, offline"; solver strength gets lost. Reuses §3.

Recommendation: Path A, with B's multi-site planning as second milestone and C's codex as a thin layer that comes almost free with the Docs model. Reasons: parser + catalog are hardest-won and unique offline; desktop app makes sense when it does what a website can't; "everything" is most believable when the app knows your world. Day-one: freshness fingerprint covering everything the solver uses; fixture tests that fail loudly when missing.
Open questions: save-less planning first-class or fallback? read built factory? modded saves? platforms (Windows/Linux/Steam Deck, Steam+Epic)? patch-follow speed (1.3)? bundled game data licensing vs reading from install?
